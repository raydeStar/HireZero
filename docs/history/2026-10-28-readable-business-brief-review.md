# Readable saved business briefs and the approved-site walkthrough

## Shipped change

[ADR 0159](../adr/0159-readable-saved-business-briefs.md) makes saved drafts readable before editing, with visible
verification labels and expandable source evidence. Unsaved local changes still reopen in the editor. Completed
research and model-request history are grouped separately; active or uncertain requests remain visible on entry.
Exact saved-version approval and owner corrections are preserved.

The owner explicitly approved the separate public-site editorial brief. That exact saved version was approved in
the installed application, then used to create a Marketing employee and its brief-based department context. This
closes the fact-review gate for this editorial pilot, not successful automatic brief generation or customer onboarding.

## Verification and installation

- Web build and both repository formatters pass.
- The fictional business-brief, full business-drafting/first-result and source-freshness browser journeys pass.
  They cover saved review mode, expandable quotation/date evidence, unfinished edits after reload, exact approval,
  generated-brief loading, uncertain-request reconciliation, corrections, hiring and first assignments.
- The changed disclosures required three test waits to open completed history explicitly. No request was replayed.
- Visual inspection caught a shared grid rule overriding the editor's hidden attribute. A scoped display rule fixes
  the duplicate form; the focused journey now checks rendered visibility as well as the attribute.
- Both local applications were updated with full data/application backups. All 146 non-web files are byte-identical
  to the prior installations; 162 staged files were verified after each install. Existing records, accounts, audits
  and the exact two-occurrence schedule were preserved without another runtime approval.
- Browser evidence and real request receipts are private and ignored. Fictional checks make no external or live
  model requests. Live pilot calls are separately owner-authorized evaluations, never routine tests.

## Native evaluation

The first plan used the default Marketing assignment with the approved website brief. Its request review showed
Codex OAuth, the Luna route, high effort, a 3,000-output-token target, a 90-second local deadline and an intended
one-existing-credit allowance. These remain soft limits. It completed with 7,404 input and 743 output tokens;
actual credit usage was not reported. Local checks counted 495 words and post sections of 70, 56 and 78 words.

The result was structurally compliant but its internal team-reminder example remained generic, and its own word
labels were inaccurate. A separate revision requests one continuous fictional marketing example, a substantive
owner correction, a completed-use tally and distinct next-week decisions. The original result and receipt remain
intact. Final revision quality and usefulness are assessed separately from format checks.

The revision completed with 8,893 input and 732 output tokens, bringing this walkthrough to two calls and 17,772
reported tokens. Both receipts report zero reasoning tokens despite the requested high effort; the application
review establishes requested settings, not a claim about hidden provider reasoning. No actual credit charge was
reported. The revised plan has a continuous example and usable learning rule, but Friday contains 92 words against
the requested 80-word maximum and introduces ordering details absent from the example brief.

A separate assistant editorial copy removes those unsupported details, shortens Wednesday and Friday, and uses
clear post headings and separated question/answer and before/feedback/after blocks. Local checks pass at 443 words,
with post sections of 62, 55 and 57 words, one open decision and a 45-minute preparation schedule. Model outputs and
receipts remain intact. The application labels this owner-side copy as owner authored; it is an assistant edit,
not yet an owner usefulness acceptance. That assessment was requested separately. Nothing was published or added
to the existing schedule.

Remaining UX observation: the generic editing form counts whitespace tokens including Markdown-only tokens,
whereas Marketing checks count visible words. The two counters can differ; the acceptance figures above use the
Marketing checker. Recommendation ordering also places incidental role keywords ahead of the explicit content
goal. These are follow-up findings, not claims of a completed customer experience.
