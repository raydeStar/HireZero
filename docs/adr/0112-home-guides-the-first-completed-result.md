# 0112 — Home guides the first completed result

Status: accepted; [fictional browser verification](../history/2026-10-26-home-first-result.md) passed.

The context-first journey must remain useful when an owner leaves onboarding or reloads. Home previously
counted any task, including a conversational turn, as the first work request and counted any approved artifact
as completion. Its final review link could be absent while an assignment waited for authorization, and an
approved result hid the guide before its task was completed.

Use ordinary tracked work for Home's first-work milestone, excluding conversational turns and setup-context
drafts, consistently with the Progress report. Reuse the role's existing first-assignment
form on Home when its active employee has a private thread and the current approved business brief supports
that role's setup contribution. Preserve the same draft key, exact context binding, preparation-only action,
allowance review and lost-response recovery. This adds no role-specific logic to the shell or Core.

Once work is saved, replace preparation with a link to the assignment. Prefer results awaiting review, then
unfinished work; retain access to terminal work that needs investigation. Open work from Home in focused work
mode. Finish the checklist only after the same tracked work task is completed and has an approved result.
An approved result alone does not complete its assignment. A chat alone does not fulfill the useful-work target.

Use the existing current-profile selector for Home's brief status, including its knowledge binding. Retired
employees do not satisfy the hiring step. Roles without a business setup contribution retain their ordinary
work entry point. Viewers do not receive the new preparation form; server authorization remains authoritative.

This improves P1.7/P1.8 and the route back to unfinished work in P2.2. Fixture completion does not establish
customer usefulness, real model quality or field-validation targets.
