# Recover the Home disclosure without losing the request

A failed model/run-terms lookup left Home displaying an error with Generate disabled and no
recovery action. The owner had to reload the page or change setup to cause another lookup.
Home now offers **Retry loading terms** beside the error. It preserves the form, reloads only
the disclosure and requires consent before Generate can prepare or dispatch work.

The fictional Home browser walkthrough injects one failed terms lookup, verifies the error on
mobile, then recovers through the button. It confirms two total terms lookups, zero work commands
during recovery, unchanged business/goal/website inputs and unchecked consent after recovery.
The subsequent website-backed run, lost-reply recovery, direct email, automatic result opening
and desktop/mobile checks still pass. No live models or external websites are used.

The web build and repository formatters pass; the existing Vite large-chunk advisory remains.
Both local installs received the sixteen web build files after verified web backups. Old assets
remain available for open tabs; services were not restarted and application data was not changed.
Both health checks pass. Private receipts and the mobile screenshot stay outside Git.

Three fresh-business first-output evaluations are prepared privately: bookshop posts, a home
organizer's service page and an illustration studio's welcome email. This cycle ran none of them;
their batch authorization is pending. Their initial outputs will remain unedited, and comparisons
will not replace first-run evidence. No new architecture decision was needed.
