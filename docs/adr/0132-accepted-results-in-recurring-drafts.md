# 0132 - Preserve accepted results when repeating work

Status: accepted, 2026-10-27.

The first weekly-plan walkthrough required editorial corrections before the result was useful. Repeating the
completed task copied its request and earlier evidence, but omitted its own approved output. The next request
could therefore lose the concrete example of the quality the owner had accepted.

New drafts opened through **Repeat this work** include the source task's approved results alongside its existing
evidence and approved dependency results. Unapproved alternatives are excluded; duplicate references are removed.
If several copies were approved, all are offered for explicit review rather than guessing which is final. Each
reference has an exact-text preview and a removal action before saving. Existing size, count, tenant, current-source
and revocation checks still apply. Long selections must be reduced explicitly, never silently truncated.

The request itself is preserved. The editor explains that recurring instructions should define what changes each
run and what a useful result contains. References remain fixed to the reviewed records; later results are not
automatically added. Separately approved documents and memory retain their existing scoped retrieval behavior.

Existing saved browser drafts and saved schedules are unchanged. Saving or following this shortcut does not
authorize, activate or execute a schedule. Finite schedule consent, per-result approval and no-replay recovery
continue through the existing workflow. This improves continuity into recurring work; it does not establish
actual output quality, customer return or paid value.
