# Artifact feedback and revision workflow

The first-result walkthrough exposed a gap: “Ask for changes” changed an artifact's status but collected no
feedback and created no follow-up assignment. ADR 0128 adds a written feedback form, member/company-scoped draft
recovery, and a separate revision request for independent measured text work. The original result and usage stay
in history. The new request appears under “Needs you” and requires its own context/model/allowance review.

Revision context contains the immediately preceding unapproved draft and the requested changes. Conversation
history is omitted so the assignment and earlier outputs are not repeated. Original approved knowledge, selected
evidence and source lineage are still checked. Feedback does not silently become company knowledge or long-term
memory. Plan, recurring and repository results retain their parent workflows.

Four focused facts cover persistence, idempotence, isolation, exact-source checks, revoked knowledge, fresh budget
roots, withheld automatic execution and multiple revisions. The related assignment, model-connection, schedule
and Today checks passed together: 53 facts, zero failures. A restricted Windows file sandbox caused DPAPI/atomic
file failures on one run; the same bounded fictional checks passed outside that file sandbox. No live provider
requests were used in those checks.

The browser walkthrough preserved an unfinished feedback form across refresh, created a revision, exposed its
feedback and previous draft in the exact context review, ran one fictional response, and retained approval after
refresh. Completion appeared in the cockpit. It also exposed two repaired defects: revision requests were missing
from “Needs you,” and generic retry could discard their source/feedback context. Layout was inspected on desktop;
this checkpoint does not claim a new mobile walkthrough.

The Release build was installed into the existing local application after an idle-work check and full backup.
Previous executables remain recoverable. Saved model accounts, existing work and audit records are preserved.
The owner's actual feedback was then saved through the supported application command against the preserved
pilot result. A separate revision was prepared but not dispatched. These mechanics do not establish improved
model output, owner acceptance, repeat usage or payment. The three-phase goal remains open.
