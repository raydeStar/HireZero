## Saved Developer review

The review captures file content against the proposed Git revision, including pre-existing uncommitted changes. It does not identify which individual actor caused a change. Added, modified and deleted UTF-8 text files include raw patches and before/after SHA-256 values. Empty-file additions/deletions retain their status even when Git emits no patch. The receipt has its own digest, and the generated work artifact includes that digest. Review approval does not commit, merge or publish code.

The pilot accepts at most 2,000 checkout entries, a 20 MiB checkout, 50 changed files and 64 KiB of patches. Baseline blob reads are bounded to 1 MiB. Binary changes, baseline symlinks/submodules, reparse paths, ambiguous paths and changed fingerprints are refused. Patches compare fixed raw temporary files outside the checkout, with external diffs, text conversion, system/global Git configuration, replacements, hooks and project clean filters excluded. This is a content review, not an index, rename or file-mode review. Repository identity and confinement remain separate gates.

Fixture validation follows a campaign brief through its admitted draft instructions, content review and exact handoff. The existing real stdio fake-runner path now verifies a persisted diff and artifact binding; a separate temporary repository verifies additions, modifications, deletions and refusal of binary changes without running project Git filters. No live provider, real project execution or deployment is used.

## Windows boundary result

The initial native check accepted the restricted named profile but could read a fictional sibling file outside the permitted root. The owner subsequently approved a process-local MXC test. With exact `windows.sandbox="mxc"` selected, the permitted read succeeded, the sibling read and scratch write failed, no write file appeared, and the owned loopback network fixture received no connection. Zero model turns or login requests were made. The owned test process exited. No saved configuration, account, service, firewall or ACL change was requested.

The connector now selects MXC through owned-process arguments and verifies that exact mode; no legacy backend fallback or wider read roots are accepted. Initial approval-review attempts were blocked before process creation. After action-specific owner authorization, the same native qualification entry point completed all four turns: two fictional employees each received their own marker, then their selected prior topic, without the other employee's markers. Reported usage was 17,572 tokens total; included usage remained available and the observed credit balance was unchanged at every before/after check. No API fallback or purchase occurred.

Native input usage was 4,355–4,400 tokens per turn despite the small supplied context. Each total stayed below the qualification's soft 5,000-token stop threshold, but the normal scheduler's 4,000-input admission bound has not been proved. The four-turn authorization is consumed. These results do not enable automatic workers, real Developer execution, a live employee queue or production deployment.
