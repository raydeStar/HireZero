# Accepted results carried into recurring work

The weekly-plan acceptance path required an edited result, but **Repeat this work** copied only the original
request and its earlier references. It omitted the output the owner had approved. A later run could therefore
lose the concrete example of the quality and detail the owner wanted.

[ADR 0132](../adr/0132-accepted-results-in-recurring-drafts.md) includes the source task's approved copies in a new
recurring draft. Unapproved alternatives are excluded. Each selected reference has an exact-text preview and
can be removed before saving. Several approved copies remain an explicit owner choice rather than an implicit
guess about which is final. Previously saved browser drafts and schedule authority are not changed.

The recurring editor asks what should be fresh each run and what a useful result contains. It distinguishes
fixed result references from later work and approved memory. It does not claim to gather audience feedback,
add future results automatically, or activate a schedule through the shortcut.

Validation: TypeScript and production build passed; all 17 existing schedule facts passed. These include actual
fictional dispatch with selected result text, revocation stopping later runs, tenant isolation and old schedule
serialization. The expanded desktop/mobile browser journey generated a fictional first result, saved and approved
an edited copy, completed the task, and repeated it. Only the approved edited copy appeared in the draft; its
exact body was previewed and bound into saved schedule authority. The unapproved original stayed out. Reload,
lost-save recovery, draft editing, two occurrences, separate result approval, pause/resume, finite allowance
settlement, source refresh and inbox navigation all passed. The mobile screenshot was inspected; there was no
horizontal overflow. The browser fixture reported zero live model calls and zero external requests.

The updated application is installed locally. All 181 staged files match, existing work and both model accounts
are preserved, and the unchanged 93-entry audit chain verifies. The previous application and a full data backup
are retained for recovery. No real recurring schedule was created or activated during delivery.

This closes a continuity defect between accepted work and recurring preparation. It does not establish the
corrected real plan's usefulness, real repeat usage, publication, revenue or the complete three-phase goal.
The owner usefulness question remains pending; no additional native request or real schedule was authorized.
